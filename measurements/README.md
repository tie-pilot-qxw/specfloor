# measurements

Every recorded run behind the paper, as the probes wrote it. 240 MB of `jsonl`
stored gzipped at 32 MB; `.sh`, `.py` and `.md` are kept plain so they read on
the web. `MANIFEST.tsv` carries the row count, the raw size and the raw SHA-256
of every file, so a decompressed copy can be checked against what was measured.

Nothing here is post-processed, with one exception: in `tk20/` and `scale/`,
probe_tk was run for its order-0 column and the order-1 fields it also emitted
are stripped on the way in (`sync_measurements.DROP_ORDER1`), so those files'
hashes describe the stripped records. The reports in the package read these
files directly, gzipped, and produce the tables; if a number in the paper
disagrees with what a report prints off this directory, the paper is wrong.

The archive is regenerated by `python sync_measurements.py <measurement_runs>` at the repository
root, which is idempotent: a file whose raw digest already matches `MANIFEST.tsv` is left alone.

```bash
python -m measurements.verify              # every number the paper reads off this archive
python -m paper.figures                    # the measurement figures
zcat measurements/t0_s6/gsm8k.t0.jsonl.gz | head -1 | python -m json.tool
```

## Two things in here that are evidence rather than data

**`*.jsonl.pre-oomfix`** are the superseded arena-hard runs from before the
`no_grad` fix in `probe_rpre`. They are kept so the recovery is checkable:
`scale/compare_rerun.py old new` verifies that the chunking is identical, that
the anchors the old run *did* keep reproduce within Monte Carlo noise, and that
the only difference is anchors gained. Gemma-4-12B gained 39 of 96 on
arena-hard, Qwen3-8B 9.

**`tk/gsm8k.t0.jsonl.CORRUPT-two-writers`** is what two probe processes sharing
one output file produce: records spliced at overlapping write offsets, some of
which still parse. It is kept because `tk_report.load` counts malformed lines
rather than skipping them silently, and this is the fixture that behaviour
exists for.

## Dated notes

The `RESULT.md`, `PREDICTION.md` and `MANIFEST.md` files, the `run.sh`
comments and `calib_20260818/derivations/` were written while the runs were
made, and are archived byte-for-byte with the runs (their hashes are in
`MANIFEST.tsv`). Section and question numbers in them (`§5.3`, `5.11`, `Q3`,
`Part III`) refer to working drafts and to a protocol document that is not
part of this repository; the table above gives each run's place in the paper.
Two of them point at a run the archive does not carry:

- `tk20/pair.py` reads `t1/`, the pre-fix run of `t1_fix/`. The fix changed
  only `T^(1)`, so `t1_fix/*.t01.m256` carries the same `T^(0)` records;
  `measurements.verify` recomputes the calibration from it
  (App. Vocabulary truncation).
- `rm_snis/RESULT.md` quotes recovery fractions under an earlier aggregation;
  `specfloor.mi_report` gives the published ones.

## Reading a record

Fields are per (anchor, slot). Every file carries `pi`, the anchor's inclusion
probability under the stratified sampler; every mean in the paper is
Hájek-weighted by `1/pi` and every interval is a cluster bootstrap over
*prompts*, because anchors from one prompt share a prefix.

```
prompt_id  t  context  stratum  pi  corpus  M  top_k
T          {order: {slot: value}}      the floor
resid      {order: {slot: value}}      top-K truncation mass, which BOUNDS
                                       |T - T~| two-sidedly. Nothing is dropped
                                       for it; see specfloor/tk_report.py
ess        {order: {slot: value}}      effective sample size of the path weights
T_split    fit on half the paths, scored on the other half
n_eff      {prefix length: value}      collision-equivalent effective support
                                       of the sampled j-token prefixes (probe_tk)
R, G       drafter risk and gap (probe_rpre)
T1         {slot: {plug, split, cov, groups}}   order-1 floor by partitioning
R_self     self-conditioned risk (probe_rpre --order 1)
S, abar    survival weights and mean accept factors (srv, rpre_o1_ours)
num, den   recovered and total missing information, nats (probe_rm)
chunk      paths per prefill, a deterministic function of (context, K, budget).
           Two runs with different chunk values consumed the sampler's random
           stream differently and are not comparable path-for-path.
```
